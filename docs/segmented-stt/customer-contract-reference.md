# Segmented speech-to-text: customer contract reference

## 1. What this document is

This is the wire contract of segmented speech-to-text, for client developers and SDK authors. Segmented speech-to-text lets a live call use a model that only transcribes files: the gateway cuts the caller's audio into utterances with its own voice detector, uploads each one and returns the text. The capability map (the data in `capability-map/` saying how each model is reached on a call) decides what a session gets, and the session reports it. This document lists every field, message, code and refusal reason the work adds to `/ws` and to `/v1/realtime`, the OpenAI-Realtime-compatible front door for Bud voice agents. It is authoritative for the wire contract and needs nothing outside this folder; chapter 5 gives the reasons and the code changes. Where texts differ, this document and `INTEGRATION_DECISIONS.md` win, and in that file Addendum B wins over Addendum A and over everything above them. Which model gets which transport, refusal or warning in each release is in `capability-map/EXPECTED_RESOLUTION.md`, generated by the reference resolver `capability-map/resolve.py`.

## 2. `ready.stt` field reference

`ready` gains one key, `stt`, after its existing fields, on each audio-enabled session the rollout switch covers. The switch is the server setting `WAAV_SEGMENTED_STT`; it *covers* a session when it is `on`, or `allowlist` with the session's deployment listed. Nothing is covered in Release 0, only allow-listed deployments in Releases 1 and 2, and every session from Release 3, when the default becomes `on` (with a release note). Without the key the gateway makes no statement. On a *gateway-endpointed* session the gateway, not the vendor, decides where utterances and turns end; every segmented session is one. Fields are present (as `null` where allowed) unless "Omitted when" applies. "From" is the first release with the field or value.

| Field | Type and values | Meaning | Omitted when | From |
| --- | --- | --- | --- | --- |
| `provider` | string | Canonical provider id after alias or deployment resolution | Never | 1 |
| `model` | string | The model that runs | Unknown to the gateway (AssemblyAI with no model picks by language), or the provider's model field is not a model (Reverie keeps an application id there) | 1 |
| `model_source` | `request`, `deployment`, `provider_default`, `substituted` | Where `model` came from. `provider_default`: the provider's answer for no model (OpenAI: `gpt-transcribe`). `substituted`: today's client replaces the id sent | Never | 1 |
| `deployment` | string | The Bud deployment name the client used | Not a named-deployment session | 1 |
| `transcription_mode` | `streaming`, `segmented`, `buffered` | `streaming`: text while the caller speaks. `segmented`: text after each pause; the gateway uploads each utterance, or commits it on a vendor socket that returns text only for committed audio (`gpt-transcribe` on OpenAI's socket when the deployment sets `latency_tier: low_latency`, Release 4). `buffered`: a plain session kept on today's buffering client (7.3); text only at `audio_end` or hang-up | Never | 1 |

| `endpointing` | `vendor`, `gateway`, `client` | Who ends utterances. `gateway`: the gateway's detector, also for a manual-mode agent and, from Release 4, live streams the gateway commits (OpenAI and Azure OpenAI live-only models; Cartesia behind `WAAV_STT_CARTESIA_MANUAL_FINALIZE`); a client running its own detector should stream all audio. `client`: only with `buffered`; keep sending `audio_end` | Never | 1 |

| `final_deadline_ms` | integer or `null` | The deadline in force (Addendum B1): how long the gateway waits for a segment's text before reporting it lost, counted from the turn's newest cut. `null` when not gateway-endpointed | Never | 1 |

| `map_version` | string | Capability map version | Never | 1 |

### Where the latency figures are counted from

*End of speech* is the caller's last voiced sample. `final_latency_typical_ms` and `final_latency_slow_ms` run from end of speech to the release of the utterance's text (an interim, or the turn's final). They include the 224 ms pause the detector waits before it cuts (the *cut pause*), because the upload starts at the cut. They exclude the end-of-turn decision; the final goes out at the later of that decision and the vendor's answer. The turn can end after 416 ms of silence when the audio end-of-turn model says the caller finished; otherwise when the text end-of-turn model says so; otherwise at the silence ceiling: 1,500 ms by default; for an agent 1,000 to 1,500 ms by eagerness, or its `max_endpointing_ms` clamped to 800 to 3,000 (exactly 3,000 reads as unset until bud-auth makes the field optional); elsewhere the request's `utterance_end_ms`, clamped alike. A row that uploads once per turn uploads after the decision. `final_deadline_ms` runs from the turn's newest cut, when `speech_end` is sent, so it excludes the cut pause. It is 6,000 ms by default; a deployment may set 3,000 to 10,000, and a value below the silence ceiling plus 2,500 ms is raised to that and reported with `deployment_setting_not_applied`. The engine reports it; the contract copies it unchanged. Every turn closes within the deadline plus 922 ms of its last voiced sample (cut pause, a 250 ms guard, 448 ms for an unconfirmed onset); that bound is not sent. So a last-resort timer one second after `final_deadline_ms`, counted from the latest `speech_end` (11 s when `null`), never fires before the gateway answers.

## 3. The OpenAI-Realtime-compatible surface

`GET /v1/realtime?model=prompt:<agent>` runs an agent's `/ws` session inside the gateway and translates its messages. `session.created` is sent before speech-to-text is resolved, so the standard `session` object is unchanged and two Bud events carry the answer, from Release 1, only on gateway-endpointed sessions. `WAAV_REALTIME_BUD_SESSION_EVENTS` (default on) turns both off.

```json
{"type":"bud.session.stt","event_id":"evt_bud_…","stt":{"…":"the ready.stt object"}}
{"type":"bud.session.warning","event_id":"evt_bud_…","code":"stt_segmented_mode","message":"…","detail":{}}
```

- `bud.session.stt` is sent once, after `session.created`, when the inner session's `ready` arrives.
- `bud.session.warning` carries each `config_warning` and `stt_warning` whose code starts with `stt_`, except `stt_buffered_until_commit` (logged only). From Release 2, `stt_segment_failed` becomes `conversation.item.input_audio_transcription.failed` on the open user item instead. A session on a streaming model gets no new event.
- Speech events stay transcript-timed in Release 1. From Release 2, `turn_start` opens the user item and sends `input_audio_buffer.speech_started`; `turn_end` sends `input_audio_buffer.speech_stopped` and `input_audio_buffer.committed`; a `turn_closed` without text closes the item, as `…transcription.failed` when its reason is `transcription_failed`.
- `error` events carry the `/ws` code in `error.code`: type `server_error` for `stt_segmentation_unavailable`, `stt_overloaded`, `stt_unavailable`, `deployment_changed`, otherwise `invalid_request_error`.
- From Release 0, a `session.update` setting turn detection on an agent admitted in manual mode on an uncovered buffering model is rejected (`stt_live_unsupported`, parameter `session.audio.input.turn_detection`); the session stays manual.
- From Release 0, a session without a voice agent naming a file-only deployment is refused at the handshake with today's HTTP status, code `stt_live_unsupported`, reason `realtime_needs_agent`. A name the caller cannot reach keeps `model_not_found`.
- There is no request-level `transcription_mode` here.

## 4. Messages new or changed on `/ws`

**`vad_event` (new).** `{"type":"vad_event","event":"turn_closed","turn_id":7,"had_transcript":false,"reason":"no_speech"}`. Besides `event` and `turn_id`: `audio_ms` (position in the received audio by detector sample count: first speech sample for start events, last for end events; absent on transcript-derived events), `sustained_ms` (`turn_start`), `discarded` (`speech_end`), `had_transcript` and `reason` (`turn_closed`).

| `event` | Sent when | Client action |
| --- | --- | --- |
| `speech_start` | Speech confirmed, 224 ms after it began | Show "listening"; keep playing |
| `speech_end` | Speech stopped at a pause and was cut; an upload starts unless `discarded: true` | Show "transcribing" |
| `turn_start` | The gateway took the speech as a caller turn: with turn-taking, at confirmation if nothing plays and after `barge_in_ms` of speech while audio plays; on plain, DAG and (in Release 1) conversation-loop sessions, after `barge_in_ms` of speech. A cough during playback gets none | Stop playback |
| `turn_end` | The gateway decided the turn is over; text and any reply follow | Show "thinking" |
| `turn_closed` | Nothing more for this turn. `had_transcript: true` right after its end-of-turn result; else `false` with `reason` `no_speech`, `transcription_failed` (every segment lost) or `ignored` (an agent did not take recognised text as input, such as "uh-huh" or its own echo; the text is not sent) | Clear indicators |

Levels (`ready.stt.speech_events`): `detector` from Release 1 on a gateway-endpointed session that is a voice agent or whose request set `features.vad_events: true` (the client's value, not a deployment's); `transcript` from Release 2, behind `WAAV_STT_TRANSCRIPT_SPEECH_EVENTS` with a release note, on a streaming session whose request set it, the start events following a turn's first non-empty result and the end events its end-of-turn result; `none` otherwise. A gateway-endpointed session always gets `turn_closed` with `had_transcript: false`. Promised order: speech events as spoken, `turn_start` before its `turn_end`, `turn_closed` with `had_transcript: true` right after its end-of-turn result; match the rest by `turn_id`.

**`stt_result` (shape unchanged).** A segmented turn sends interims (`is_final: false`), each the whole turn so far, then one result with `is_final` and `is_speech_final` true holding the whole turn. The turn's text is `segment_transcript` when present, else `transcript`; nothing marks lost words. On such a session a commit (`audio_end`, or a Realtime commit) after any audio gets exactly one end-of-turn result, empty if nothing was recognised; a commit with no new audio is ignored.

**`stt_warning` (new).** `{"type":"stt_warning","code":"…","message":"…","detail":{…}}`, `detail` optional: a problem that does not end the call. Never sent as `error`, which deployed widgets treat as a disconnect.

**`error` (additive fields).** `code`, `recoverable` and `details`, omitted when empty, so uncoded errors are byte-identical; `message` keeps its `"{code}: "` prefix. `recoverable: true`: the socket is still usable (a refusal made before the session id is stored accepts a corrected `config`). `false`: the session is over or will never transcribe.

**`config_warning` (new codes).** Same shape, before `ready`, at most once per code, in section 5's order, `stt_setting_not_applied` last: `stt_buffered_until_commit`, `stt_transcription_mode_invalid`, `stt_transcription_mode_ignored`, `stt_mode_unavailable`, `stt_placeholder_model_ignored`, `stt_capability_assumed`, `stt_model_deprecated`, `stt_transport_fallback`, `stt_segmented_mode`, `stt_latency_slow`, `stt_fields_reduced`, `stt_min_billed_duration`, `stt_capacity_low`, `stt_detector_fallback`, `stt_setting_not_applied`. A session on today's client that used no new field gets only `stt_buffered_until_commit`; its other facts become notices, or log entries when uncovered.

**Other changes.** `agent_response_started` and `agent_response_done` gain `kind: "notice"` (Release 1, gateway-endpointed agents): the lost-turn notice, and from Release 2 the holding phrase. `agent_paused` and `agent_resumed` are reserved for Release 6. `protocol_version` stays `"1.0"`.

## 6. Reasons inside `stt_live_unsupported`

`details.reason` says what is true for this session (Addendum B10). Rows store `client_not_implemented`; the resolver substitutes `not_covered_yet` at run time when the rollout switch is the cause. Release 0 refuses sessions the map records as unable to work today, plus, by choice pending sign-off, `/ws` voice agents with automatic turn detection on a buffering model.

| Reason | Meaning | Examples, and when it stops |
| --- | --- | --- |
| `not_covered_yet` | The switch does not cover the session, and a covered one would get a transport in this release. The text may say "ask the operator to enable segmented speech-to-text" | From Release 1, an agent with automatic turns on an OpenAI or Groq file model off the allow-list. Stops when covered |
| `client_not_implemented` | No gateway client can serve this model on a live call in this release; the map says whether a later release adds one. The text never tells a covered session to ask the operator; it says segmented speech-to-text for this provider is not available in this release | Release 0 refusals of OpenAI, Groq and ElevenLabs file models; OpenAI and Azure OpenAI live-only models until 4; Deepgram `whisper*` until 3; Bhashini, FPT.AI, NAVER `csr`, NECTEC `partii4` agents with automatic turns, and Viettel and other NECTEC ids, until 5. Never in this plan: NAVER CLOVA Speech short, long and streaming, Huawei `chinese_16k_conversation`, Speechmatics `linden-1`, self-hosted Kyutai, Deepgram Flux, unknown ElevenLabs realtime ids |
| `async_only` | The vendor's only file interface is a slow job | Amazon Transcribe, Rev AI, iFlytek, Gladia `solaria-3`, AssemblyAI `universal-2`; Yandex `deferred` from 3 |
| `language_not_live` | The language is batch-only at the vendor | From 3: Amazon Transcribe, Rev AI, iFlytek |
| `provider_not_built` | The gateway cannot build or reach this vendor | Not planned to change |
| `disabled` | Deliberately not offered on calls, or not in this region | From 3: Rev AI `human`, Sarvam `saaras:v2.5` (translation only) |
| `model_not_served` | The setup probe found the model is not served | From 2 |
| `realtime_needs_agent` | `/v1/realtime` without an agent named a file-only deployment | From 0; use `/ws` or an agent |

## 7. Worked sessions

`→` is from the client, `←` from the gateway, `…` marks fields that do not matter here; times count from the start of speech.

### 7.1 A streaming model

Deepgram `nova-3` in Release 3 (covered by default), `WAAV_STT_TRANSCRIPT_SPEECH_EVENTS` on. No `config_warning`.

```text
→ {"type":"config","stt_config":{"provider":"deepgram","model":"nova-3","language":"en-US",…,"features":{"vad_events":true}}}
← {"type":"ready","protocol_version":"1.0",…,"stt":{"provider":"deepgram","model":"nova-3","model_source":"request","transcription_mode":"streaming",…,"interim_results":"live","endpointing":"vendor","speech_events":"transcript","confidence_source":"vendor","latency_class":"realtime","final_latency_typical_ms":null,"final_latency_slow_ms":350,"final_latency_slow_percentile":99,"latency_basis":"seed","final_deadline_ms":null,"lifecycle":"ga",…}}
← {"type":"stt_result","transcript":"I'd like to","is_final":false,"is_speech_final":false,"confidence":0.82}
← {"type":"vad_event","event":"speech_start","turn_id":1}
← {"type":"vad_event","event":"turn_start","turn_id":1}
← {"type":"stt_result","transcript":"I'd like to change my booking.","is_final":true,"is_speech_final":true,"confidence":0.97}
← {"type":"vad_event","event":"speech_end","turn_id":1}
← {"type":"vad_event","event":"turn_end","turn_id":1}
← {"type":"vad_event","event":"turn_closed","turn_id":1,"had_transcript":true}
```

Without `vad_events` the client gets today's messages plus `ready.stt`; an uncovered session gets today's bytes.

### 7.2 A segmented model on a voice agent

A `/ws` voice agent with automatic turn detection on an allow-listed ElevenLabs `scribe_v2` deployment, language `en`, Release 1 or later. The caller speaks for 2,400 ms; nothing is playing.

```text
→ {"type":"config",…}   (the agent supplies the transcription deployment)
← {"type":"config_warning","code":"stt_segmented_mode","message":"Model 'scribe_v2' (elevenlabs) transcribes uploaded files only, so …","detail":{…}}
← {"type":"ready",…,"stt":{"provider":"elevenlabs","model":"scribe_v2","model_source":"deployment","transcription_mode":"segmented","requested_mode":"auto","requested_mode_source":"default","interim_results":"per_segment","endpointing":"gateway","speech_events":"detector","barge_in_ms":500,"detector":"silero","confidence_source":"none","latency_class":"slow","final_latency_typical_ms":null,"final_latency_slow_ms":2010,"final_latency_slow_percentile":99,"latency_basis":"seed","final_deadline_ms":6000,"lifecycle":"ga","capability_source":"exact","streaming_alternatives":["scribe_v2_realtime"],"map_version":"…"}}
  224 ms   ← {"type":"vad_event","event":"speech_start","turn_id":7,"audio_ms":12000}
  224 ms   ← {"type":"vad_event","event":"turn_start","turn_id":7,"audio_ms":12000,"sustained_ms":224}
  2,624 ms ← {"type":"vad_event","event":"speech_end","turn_id":7,"audio_ms":14400}
  decision ← {"type":"vad_event","event":"turn_end","turn_id":7,"audio_ms":14400}
  later of decision and answer
           ← {"type":"stt_result","transcript":"I'd like to change my booking.","is_final":true,"is_speech_final":true,"confidence":1.0}
           ← {"type":"vad_event","event":"turn_closed","turn_id":7,"had_transcript":true}
```

The decision comes between 416 ms after end of speech and the agent's silence ceiling. Had the agent been speaking, `turn_start` would come at 512 ms and cut the reply. If the upload fails after its retry, or no text comes within 6,000 ms of the cut, the client gets `stt_warning` `stt_segment_failed` and `turn_closed` with `"had_transcript":false,"reason":"transcription_failed"`; the agent speaks a notice, and a third such turn in a row ends the call with `stt_unavailable`, `repeated_loss`. Off the allow-list this agent is refused with `stt_live_unsupported`.

### 7.3 A plain `/ws` session on a buffering model

A *plain* session has no voice agent and no conversation loop: the client consumes transcripts and ends each utterance with `audio_end`. On a model whose only client buffers until the stream ends, it keeps that client even when covered, unless the request sets `transcription_mode: "segmented"` (Addendum B4), so the gateway never ends a turn on a pause inside one press. OpenAI `gpt-transcribe`, Release 3:

```text
→ {"type":"config","stt_config":{"provider":"openai","model":"gpt-transcribe","language":"en",…}}
← {"type":"config_warning","code":"stt_buffered_until_commit","message":"Model 'gpt-transcribe' (openai) transcribes uploaded files only, and this session uses its buffering client. Text is returned when the client sends audio_end or disconnects. For text after each pause without audio_end, set transcription_mode to segmented or use a streaming model.","detail":{"provider":"openai","model":"gpt-transcribe"}}
← {"type":"ready",…,"stt":{"provider":"openai","model":"gpt-transcribe","model_source":"request","transcription_mode":"buffered",…,"interim_results":"none","endpointing":"client","speech_events":"none","confidence_source":"none","latency_class":"unknown","final_latency_typical_ms":null,"final_latency_slow_ms":null,"latency_basis":"none","final_deadline_ms":null,"lifecycle":"ga",…}}
→ (binary audio while the button is held)
→ {"type":"audio_end"}
← {"type":"stt_result","transcript":"Cancel my order.","is_final":true,"is_speech_final":true,"confidence":1.0}
```

No `vad_event` is sent: the session is not gateway-endpointed. Later presses repeat the last three lines once the Release 0 fix keeping the OpenAI and Groq clients' callbacks across `audio_end` ships (Addendum B5). An uncovered session gets the same messages without the `stt` key; its warning suggests a streaming model or asking the operator. With `transcription_mode: "segmented"` (Release 2) the session goes to the engine: turns may end at pauses inside a press, and each `audio_end` still gets one end-of-turn result.
