# Things the draft schema could not express

Reported by the nine agents that built the capability map rows (402 rows, 35 files) against schema v1. Each line is one gap, grouped by the builder that reported it.

## Builder for alibaba-cloud+3

- No place for gateway-side model-string rewriting. Alibaba's client turns five valid vendor ids of asynchronous models (paraformer-v2, paraformer-8k-v2, paraformer-v1, paraformer-8k-v1, fun-asr) and several shorthand strings into streaming models; NECTEC turns every unknown string into partii5. Rows keyed by wire id therefore say 'no live path' for strings that stream today.
- No region dimension. Alibaba model availability, hosts and keys differ between Singapore, Beijing and US (Virginia); the US region has no legacy host and needs a workspace id. Recorded in notes only.
- dialect.language_param has no value for Alibaba's language_hints (a list, used by the run-task socket and the flash HTTP models). Recorded as 'languages', the nearest value.
- latency cannot hold a vendor-published average or a handful of probe samples without claiming a P99. Viettel's file endpoint (about 30 s average, probes of 15.7 s and 22.5 s) is therefore class 'unknown' although all evidence says slow; the figures are in latency.conditions.
- quality_signals has no value for a vendor's binary no-speech status (FPT status 1), so the only usable drop signal for FPT is in notes.
- upload cannot express MP3 as the preferred container (FPT may accept only MP3), nor the request envelope (raw body, multipart, base64 inside JSON). vendor_param holds one key=value pair; Alibaba's flash shape needs two (format and sample_rate).
- No field for vendor terms that bar production use. NECTEC is free for study only, prohibits commercial use and may reuse uploaded audio; 'evaluation-only' lives in notes.
- lifecycle cannot express a planned retirement without a date (Alibaba Gummy), an endpoint that is dead without an announcement (NECTEC partii5, recorded as preview with no transports), or separate the vendor-named replacement from a live-capable one (retiring qwen3-asr-flash snapshots point to asynchronous fun-asr).
- billing is per row, so bills_silence cannot differ between the streaming and the file transport of one model (Viettel); left null.
- Vendors with no model parameter: when the gateway has no product identifier (Viettel) only a default row is possible, and it must be labelled 'assumed' even though its facts were probed. The default_model description says null for such vendors, yet FPT and NECTEC need a gateway identifier there.
- limits_scope has no 'account' value. Alibaba counts rate limits across the whole primary account, not per key; recorded as 'organisation'.
- interim_results holds one value per transport. It cannot separate what the vendor offers from what the gateway adapter delivers (Alibaba Qwen realtime offers live interims the client drops; qwen3-asr-flash can stream text after upload). Rows record what the adapter delivers.

## Builder for deepgram+3

- Billing is one block per row, but price and silence billing differ per transport (AssemblyAI universal-3-5-pro has three prices; Cartesia ink-whisper's file endpoint costs half the socket rate). I described the first listed transport and put the rest in billing.notes. A per-transport billing block is needed.
- dialect.language_param has no value for AssemblyAI Sync's language_codes or Deepgram Flux's language_hint. I used the nearest value (languages, language) and named the real wire field in provenance.unverified.
- Limits hold one number, but vendors publish them per plan (Cartesia 8/12/20/60; Gladia 3 or 25 jobs; AssemblyAI 5 or 200 jobs; Deepgram Whisper Cloud 3, 5 or 15). I recorded the lowest paid-plan figure and listed the others in provenance.unverified.
- limits_scope has no 'account' value. I used 'organisation' for AssemblyAI, Cartesia and Gladia, whose limits apply to the whole account.
- No field for a host or region restriction per transport. Deepgram Whisper Cloud is available on the North America host only, and AssemblyAI uses three different hosts (streaming, sync, api), each with regional variants.
- No model alias concept and no language-dependent default. AssemblyAI's u3-sync-pro and u3-pro needed full rows, and provider.default_model cannot say 'the English model for English, the multilingual model otherwise'.
- lifecycle.status has no 'unknown' or 'legacy' value. Gladia solaria-fusion, present only in a specification list, got no row; Deepgram's legacy families and AssemblyAI's legacy aliases are recorded as ga.
- No per-model language constraint. Gladia solaria-3 needs exactly one of five languages; Cartesia ink-whisper needs a language and cannot detect one. The resolver needs at least 'language required' and 'single language only'.
- The adapter naming rule gives one streaming and one file adapter per provider. I added stream_deepgram_flux, stream_cartesia_turns and segmented_assemblyai_async for a second socket or a second file interface at the same vendor.
- gateway_client.status has no value for 'connects but serves a different model'. I used known_broken on AssemblyAI and Gladia rows where the client silently substitutes its default model.
- No field for an idle-socket timeout (Cartesia closes idle sockets after 3 minutes; stored in vendor_timeout_seconds) or for poll timing on async_poll transports (stated in segment_profile.rationale).
- latency has one basis and one source, so a vendor median and a third-party 99th percentile cannot be stored together (AssemblyAI Sync: vendor 134 ms median, Pipecat 650 ms P99).

## Builder for extras

- No way to say "unclassified: take today's path unchanged". A transport forces values for interim_results, endpointing_owner, vendor_turn_signal and dialect.language_param, and lifecycle.status has no unknown. Smallest change: an optional row-level boolean (for example passthrough) that lets transports be empty without no_live_path_reason and tells the resolver to call the existing factory unchanged.
- provenance.sources accepts only https URLs, so first-party evidence (WaaV Infer engine source, gateway code) cannot back a documented row. waav-infer rows are forced to assumed and would raise the assumed-capability warning on every session. Smallest change: optional provenance.code_refs (repository path:line strings) that also satisfies the documented and probed minimum-source rule.
- The deployment override object is not in the schema. Azure OpenAI needs a declared base model (underlying_model) because the wire id is a deployment name; socket profiles need an explicit socket address (realtime_url) because a profile carries none. Propose a $defs/deployment_override with profile, underlying_model, realtime_url, latency and limits.
- Socket transports cannot record the audio format the server requires (vLLM, NVIDIA NIM and WhisperLiveKit 16 kHz; OpenAI, Azure and speaches 24 kHz), although the speech-to-text leg receives caller-rate audio. upload exists only for file transports. Smallest change: optional stream_audio {encoding, sample_rate_hz, channels} on live_stream and vendor_segmented transports.
- For OpenAI-compatible servers the accepted request fields are a property of the server software, not of the model id, but dialect lives in the row. Worked around with named file profiles. Alternative smallest change: let the deployment override carry dialect (language_param, context_params, response_formats), filled by a registration-time probe.
- dialect.language_param names the field but not the code format. NVIDIA NIM requires a BCP-47 tag (or a model) while OpenAI-shaped servers take ISO 639-1. Smallest change: optional dialect.language_format with values iso639_1 and bcp47.
- billing.unit has no value for an operator-owned server with no vendor meter; self_hosted and waav-infer rows record unknown, which reads as missing data. Smallest change: add the enum value none.
- lifecycle cannot express "generally available with a published retirement date", which is Azure's normal state. Azure whisper and the gpt-4o rows are marked deprecated so a warning fires. Either add a status such as retiring, or state that the resolver warns whenever shutdown_on is near regardless of status.
- Profiles are bare transport objects with no provenance, so the sources and unverified fields behind a profile have nowhere to live. Smallest change: allow an optional provenance object beside each profile, or make profiles {transport, provenance}.
- The schema covers an empty transport list (no_live_path_reason) but not a row whose transports are all disabled, which is every row in these files today. The resolver needs a stated rule: no enabled transport means a named refusal built from the first transport's disabled_reason.
- The planned check that every adapter id exists in the gateway's adapter registry conflicts with rows that truthfully list adapters not yet written (commit_vllm, stream_nvidia_nim, commit_speaches, stream_kyutai_moshi, commit_waav_infer). The registry needs a planned state, or the check must skip transports whose gateway_client.status is not_implemented.

## Builder for gnani+3

- Matching: the rule that strips a leading '<provider>/' from the model breaks Bhashini. Eight wire ids begin with 'bhashini/' and four with 'ai4bharat/', a registered alias. Rows are keyed by the full wire string, so the resolver must try the unstripped id first or exempt this provider.
- No way to mark a vendor that has no model parameter. Reverie's only row is the wildcard, which the rules force to confidence 'assumed', so every Reverie session would raise the assumed-capability warning although the row is documented. Viettel has the same shape.
- Reverie's session model field holds the customer's app id, a credential (gateway/src/core/stt/reverie/config.rs:515-521). The planned counter and warning for unknown model ids would publish it. The map needs a provider flag meaning 'do not treat or expose the model string as a model'.
- dialect.language_param lacks the real wire names: Reverie src_lang and Bhashini sourceLanguage were recorded as source_lang, and the Gnani WebSocket header lang_code as language_code. The exact name is in each transport's notes.
- dialect.context_params has no value for vendor vocabulary-biasing fields with other names. Gnani bias_list, Phonexia preferred_phrases and additional_words, and Bhashini hotword_list (Hindi only, one service) were recorded as keyterms, with the wire name in notes.
- latency cannot hold a vendor claim that has no percentile. Gnani states about 300 to 500 ms from end of speech to transcript on its socket. I kept basis unmeasured and put the claim in latency.conditions rather than write it as ttfs_p99_ms.
- billing is per row, but it differs by transport. On Reverie the file upload bills only uploaded speech, while the stream sends all call audio. I recorded the value for the first-listed transport and explained the other in billing.notes.
- lifecycle.status has no value for 'legacy, undocumented, no deprecation notice' (Gnani 'default' is recorded as ga and flagged) or for on-premises 'end of support' (Phonexia EN_US_6 is recorded as retired, with shutdown_on set to the end-of-support date).
- Adapter naming has no slot for a second vendor-socket client when the provider's existing streaming client speaks a different service. I used stream_gnani_vachana for the unwritten Vachana WebSocket client and kept stream_gnani for the legacy gRPC client.
- No transport type for the client a live session gets today when it neither streams nor uploads per utterance. Bhashini's existing client buffers the call and uploads at hang-up; it appears only in notes, so the map cannot say 'existing client, known broken for live calls'.
- On-premises vendors: Phonexia limits are configurable deployment defaults, and on gRPC the model (Whisper) or language (6th generation) is fixed per endpoint, not per request. The schema has no field for endpoint-bound model or language; this is in notes and limits_scope 'deployment'.
- upload.preferred.vendor_param is defined as a form field, but Reverie needs a header (format=16k_int16) and Bhashini a JSON field inside a base64 JSON body after a separate configuration call. Body encoding and the prerequisite call are carried only by dialect.wire and notes.

## Builder for microsoft-azure+3

- No language dimension on a row or transport. Google chirp_2 streams only 16 languages and needs the file call for the rest; Amazon has 18 language codes that exist only in its batch API; Speechmatics 'auto' is batch only. A row cannot say 'stream these languages, upload the others'.
- No region or location dimension. Azure Fast Transcription exists in 22 of 33 regions (MAI and LLM Speech in six); Google model availability depends on recognizer location; Amazon cannot stream 45 languages in five regions; Speechmatics melia-1 and oak-1 exist only on EU1 and US1.
- Billing is per row but differs per transport. Azure real-time and Fast Transcription use different meters, Speechmatics realtime and batch are different product types, and bills_silence is true-ish for a stream and false for uploads. unit, pricing_key and bills_silence can describe only one transport.
- providers.default_model says null when the vendor has no model parameter. An empty model would then match only the provider default row, whose confidence must be 'assumed', warning on every session. I set gateway sentinels instead: microsoft-azure 'default', aws-transcribe 'standard'.
- dialect.language_param has no value for Azure 'locales' or Google 'language_codes' (both recorded as 'languages'), no 'unknown' value, and cannot express Speechmatics melia-1 and oak-1, where language is fixed to 'multi' and the customer's language goes in a separate language_hints field.
- limits has no per-second rate. Amazon's 25 requests per second and Speechmatics' 10 new jobs per second were converted to per-minute values, which hides the burst limit. limits_scope has no value for a vendor resource or account per region (Azure Speech resource, AWS account, Google project and region).
- latency cannot hold a vendor's typical, non-P99 figure. Speechmatics claims about 250 ms after ForceEndOfUtterance and Google states 30 seconds of audio in 15 seconds; both are recorded as unmeasured with the claim in conditions. Pipecat figures are per provider, not per model.
- upload.accepted lacks amr, wma, speex and mov, which Azure, Google, Amazon and Speechmatics accept. upload.preferred cannot say 'send at the call's native rate'; Google advises that 8 kHz telephone audio should not be resampled.
- No field for vendor data retention or required clean-up. Speechmatics batch keeps audio and transcripts for 7 days unless each job is deleted, while its realtime socket stores nothing; I put this in the segment profile rationale.
- No explicit refusal reason for a row whose transports are all disabled (no_live_path_reason is tied to an empty list), and no re-check date for volatile rows such as Speechmatics melia-1.
- Gateway-side model aliases cannot be expressed without ambiguous globs. The Speechmatics client accepts any id containing 'standard' or 'enhanced', plus std, enh and high, and reads nova-3 as unset; without resolver normalisation those sessions fall to the default row.
- quality_signals cannot mark a field that is returned but meaningless: Azure LLM Speech confidence is always 0, and Google says the Chirp confidence value is not a true confidence score. I left those signals out.

## Builder for openai+2

- limits has no tokens-per-minute field. OpenAI gpt-4o-transcribe at usage tier 1 allows 10,000 tokens per minute, which binds long before its 500 requests per minute; I could record it only in notes.
- limits has no per-day or per-minute audio fields: the Groq free plan allows 2,000 requests per day and 28,800 audio seconds per day, and OpenAI gpt-realtime-whisper allows 100 audio minutes per minute.
- Limits are single numbers, but vendors vary them by plan or usage tier (Groq free 20 versus Developer 400 requests per minute; ElevenLabs concurrency 8 to 60). The rows record the lowest paid plan. A plan-keyed table, or a required deployment override, would be more honest.
- billing is per row, not per transport. gpt-transcribe bills uploaded segments on the file route but an undocumented rate card on the Realtime socket, and bills_silence can differ between a row's streaming and commit transports.
- There is no field for the audio format a socket transport accepts (OpenAI Realtime: 24 kHz PCM or G.711 only; ElevenLabs: PCM at 8 to 48 kHz or 8 kHz mu-law). upload exists only for file_upload, so the resampling requirement lives in notes.
- quality_signals_require is one flat list, not keyed by signal. ElevenLabs audio-event tags need tag_audio_events=true, which the live request should turn off, so I left that signal out rather than force the setting on.
- There is no field for conditional minimum billing or surcharges. ElevenLabs bills at least 20 s per request above 100 key terms and at least 10 s with transcript_edit; billing.min_billed_seconds holds one unconditional number.
- No field says what a session gets when every transport of a row is disabled. Today OpenAI and Groq sessions start and never transcribe, and ElevenLabs file models fail at setup. no_live_path_reason applies only to an empty transports list.
- There is no field for context limits that the request builder needs: the 224-token prompt cap (whisper-1 and Groq) and the ElevenLabs key-term caps (1000 on the file endpoint, with billing changing above 100).
- limits_scope is single-valued. OpenAI defines limits at both organisation and project level, and ElevenLabs states them per plan; I recorded organisation and flagged the ElevenLabs mapping as an inference.
- gateway_client.status has no date. The ElevenLabs socket client was verified live on 2026-06-04 and changed afterwards; a last_verified_on field would let CI flag a stale verified_live claim.
- lifecycle cannot mark a deprecation as inferred (the gpt-4o-mini-transcribe-2025-12-15 snapshot is assumed to be removed with its alias) and has no value for a model that is served but not recommended (gpt-realtime-whisper).

## Builder for revai+3

- No way to mark a model id as known to be invalid. The gateway emits or accepts ids the vendor does not have (IBM es-LA, zh-CN, ar-MS and hi-IN _Multimedia language defaults; AmiVoice -a-finance, -a-insurance and four more). Lifecycle has no value for this, so these ids got no row and fall to the provider default.
- Lifecycle 'deprecated' requires a date, but Sarvam publishes none. For saarika:v2.5 I used the 2026-06-29 changelog entry and flagged it as unverified; saaras:v2.5, which 'will be deprecated soon', is left as ga. A 'deprecation announced, no date' state is missing.
- Billing is per row, but minimum charge and silence billing differ by transport: Rev AI bills a 15 s minimum per stream connection, Sarvam 1 s with unclear scope, IBM bills silence on a socket but only padding on upload. I described the first enabled transport and put the rest in billing.notes.
- provider.default_model is a single string. IBM's empty-model default depends on the session language (a _Multimedia id per locale, four of them invalid). I recorded en-US_Multimedia and explained the rest in notes.
- Limits hold one number per field. Vendor plan tiers cannot be expressed (Sarvam 60, 100 or 4,000 requests a minute and 20 or 100 sockets; IBM Plus 100 concurrent, Premium unlimited). limits_scope has no value for a vendor account or service instance, nor for a limit shared between socket and HTTP.
- No field for a model's minimum or allowed input sample rate (IBM multimedia needs 16 kHz; eight AmiVoice engines are 16 kHz only) or for the encodings a socket accepts (Sarvam's client rejects mu-law). This matters because streaming transports forward audio at the caller's rate.
- quality_signals has no name for no-speech indicators that are not Whisper-style: IBM audio_metrics.speech_ratio, AmiVoice body code 'o', Sarvam's empty transcript. There is also no place to say a vendor reports failure in a 200 response body (AmiVoice).
- A transport cannot name the vendor endpoint. Sarvam's legacy and realtime sockets serve the same model id with different wire formats and language notation (unknown and od-IN versus auto and or-IN). I used one commit_sarvam adapter id and notes. dialect.language_param also cannot express the hyphenated language-code parameter.
- interim_results has no 'unknown' value. For AmiVoice batch engines on the socket, interim events are unconfirmed; I recorded 'live' and listed it as unverified.
- gateway_client.status has nothing between wire_tested and known_broken for a client whose wire format is right but which has a call-ending defect found by reading (IBM: transcription stops after 30 s of silence). I used wire_tested or unverified with notes.
- A row whose transports are all disabled (every AmiVoice row; Sarvam saaras:v3-realtime) has no row-level refusal text; no_live_path_reason is defined only for an empty list, so the customer-facing reason has to be assembled from each disabled_reason.
- Smaller gaps: context_params has no value for stored vocabulary ids (Rev AI custom_vocabulary_id, IBM language_customization_id, AmiVoice profileId); upload.accepted lacks AMR and WMA (Sarvam); there is no minimum upload size in bytes (IBM 100 bytes).

## Builder for tencent+3

- No site or region dimension. Tencent's two synchronous file APIs and its 200-versus-20 streaming concurrency depend on China site versus international site; Huawei models are valid per region (streaming English only in cn-north-4, file English only in cn-east-3). I recorded this in notes, so a resolver cannot act on it.
- Billing is per row, not per transport. Tencent's socket and flash bill per second while SentenceRecognition bills per call; Huawei and Baidu sockets bill by duration while their file APIs bill per call. Row billing describes the first-listed transport and the rest sits in billing.notes.
- One adapter id per provider cannot name two synchronous file APIs (Tencent flash versus SentenceRecognition; Baidu server_api versus pro_api). I distinguished them with dialect.wire, so segmented_tencent and segmented_baidu must dispatch on it. There is also no field for a required token scope (Baidu pro needs brain_enhanced_asr).
- lifecycle 'deprecated' requires a date. Huawei calls english_8k_common, and chinese_16k_common and chinese_8k_common on the socket, legacy models without giving one, so those rows stay 'ga' with a note. A 'legacy, date unknown' state is missing.
- No fields for socket pacing and idle rules, which a gateway-driven commit transport must obey: Tencent at most 3 s of audio per second and 15 s idle; Huawei 20 s idle; iFlytek 1280 bytes per 40 ms and 10 s idle. There is also no flag for 'one connection per utterance'.
- limits_scope has no 'account' or 'application' value. Tencent limits are per account (AppId), recorded as organisation; Baidu counts per AppID application, recorded as credential; iFlytek does not say, recorded as unknown.
- Enumerations are too narrow: upload.accepted lacks amr, speex and silk (accepted by Tencent, Baidu, Huawei); context_params cannot express a pre-registered vocabulary id (Huawei vocabulary_id, Baidu lm_id, Tencent hotword_id) or the vendor's wire name (hotword_list); billing.unit has no 'audio duration, granularity unpublished' (Huawei real-time).
- Key normalisation misses two cases: Huawei models may carry a region suffix (model@region, gateway/src/core/stt/huawei_cloud/config.rs:777-783) that must be stripped before lookup; Tencent ids are case-sensitive on the wire (16k_zh-TW, Hy-ASR-3.0-preview) while matching is case-insensitive, so adapters must send the row's spelling.
- providers.default_model is described as null when the vendor has no model parameter, yet the resolver still needs a row for an empty model. For iFlytek I set it to the gateway's product key 'iat' and keyed rows by business.domain; the description should allow that.
- gateway_client.status cannot separate 'sessions start today but output is wrong' (Tencent; iFlytek after the first utterance) from 'cannot connect at all' (Huawei China regions). All four streaming clients are known_broken, hence disabled, which leaves no enabled transport for any of these providers; the resolver needs an explicit policy for that state.
- segment_profile has no 'merge segments shorter than N seconds' field, and the audits recommend merging for per-call billing (Huawei, Baidu, Tencent SentenceRecognition). I kept per-pause uploads and explained why in the rationale; only billing.min_billed_seconds (Tencent flash, 1 s) carries a merge hint.
- A model whose file-only status depends on unverified socket behaviour (Baidu 1637, 1837, 1737) has no dedicated field. I expressed it through transport order (file upload first) plus provenance.unverified and confidence 'assumed'.

## Builder for yandex+3

- No way to record a legacy client that is neither a streaming client nor the planned adapter. For Yandex, Sber and NAVER the client the standard factory returns today is a buffering REST client on a timer. I left it out of transports and described it in notes; the resolver needs an explicit 'never select today's client' marker for such providers.
- billing.min_billed_seconds cannot express a billing increment. Yandex and NAVER round every request up in 15 s units, so a 16 s upload costs 30 s. A separate rounding-increment field is needed for correct metering and for the merge policy.
- billing is per row, but it differs per transport. T-Bank has a stream tariff and a lower file tariff, and bills_silence is true for the stream and false for uploads. I set it for the first listed transport and explained the other in notes.
- limits has only requests_per_minute and audio_seconds_per_hour. Yandex quotas are per second (20 synchronous, 40 streaming), which a per-minute figure understates for bursts; NAVER CSR quotas are per month and per day (300,000 and 30,000 audio seconds). I converted the first with a note and left the second null.
- No provider-level prerequisite or availability fields. Sber and T-Bank need the Russian Trusted Root CA added for their hosts before any transport can connect, and Sber has been closed to new customers since 2026-07-15. Both facts live only in notes.
- upload.preferred.vendor_param holds one form field. It cannot express a required Content-Type header that differs from the container (NAVER needs application/octet-stream; Sber needs audio/x-pcm;bit=16;rate=N) or two required parameters (Yandex needs format=lpcm and sampleRateHertz).
- lifecycle cannot express a rolling tag. Yandex 'general:deprecated' is a current tag that always points at the previous version, supported for two weeks after each update; status 'deprecated' requires a date that does not exist. I recorded 'ga' with an explanation.
- limits cannot vary by account type. Sber allows 10 parallel streams for legal entities and 5 for individuals per its documentation (50 and 1 per its FAQ), selected by OAuth scope. One number per transport forces a conservative guess; I recorded 5.
- quality_signals cannot mark a confidence that is returned but is not a probability. T-Bank returns a 'relative confidence factor' (word-level values may be negative) that must not be thresholded. I left the list empty, which makes the customer-facing confidence flag false although a value exists.
- match.model assumes a vendor wire string. NAVER has no model parameter (keys are gateway product aliases), T-Bank's key is a placeholder that must never be sent, and Sber's customer-facing model field is the OAuth scope today. A flag saying 'gateway alias, do not send' would help; provider.default_model's description (null when no model parameter) also conflicts with resolving an empty model to an alias.
- vendor_turn_signal has no 'unknown' value. Yandex's end-of-utterance classifier and NAVER's 'semanticEpd' settings are not described well enough to choose between 'silence' and 'semantic'; I chose one and listed the field as unverified.
- upload.accepted lacks several formats the vendors list: AC3 (NAVER), G.711 A-law and mu-law and G.729 (Sber), AMR and AMR-WB (T-Bank). They are irrelevant to the gateway's own uploads, so I omitted them.

# What the auditors changed and still doubt

## Auditor for alibaba-cloud+3

- alibaba-cloud: The summary I was given is stale: the file has 50 rows, because eight pattern rows were added after it was written. I kept them. They are inferences from vendor naming, marked assumed, with distinct literal lengths (24, 20, 18, 17, 15, 11, 10, 9), so precedence never depends on file order.
- alibaba-cloud: qwen3-asr-flash-realtime, the gateway default, is disabled as known broken on a static reading: emotion is declared as a struct (messages.rs:224, :238-246) and the fact-check says the vendor sends a string. I confirmed the types, not the vendor event. One unit test settles it. The W3 design keeps known-broken native clients enabled with a warning; the row rules forbid that.
- alibaba-cloud: paraformer-v2, paraformer-8k-v2, paraformer-v1, paraformer-8k-v1 and fun-asr: the rows say no live path, which is true of the vendor model, yet sessions naming them stream today through the client's rewrite. The W3 resolver looks up the unchanged string and pins 'no session that works today is refused'. One of the two must change.
- alibaba-cloud: The shorthand strings qwen3-asr, qwen-asr, paraformer, paraformer-8k and funasr have no rows because they are not vendor ids. Without resolver-side rewriting they fall to the default row, and the last three break once the file adapter is enabled there. The schema needs a model-alias table.
- alibaba-cloud: Thirteen ids retire on 2026-10-10, seven days from now; their rows must become retired then. The stable aliases qwen3-asr-flash, qwen3-asr-flash-realtime, fun-asr-realtime and fun-asr are described as equal to retiring snapshots. What they resolve to afterwards, and whether the US (Virginia) route survives, is unconfirmed.
- alibaba-cloud: Limits published as 20 requests per second are stored as requests_per_minute 1200. A limiter that allows 1200 in one burst would exceed the vendor limit, so it must smooth per second. limits_scope 'organisation' stands for the vendor's whole primary account.
- alibaba-cloud: interim_results is 'none' on the qwen3-asr-flash file rows although the vendor can stream the text of a completed upload. The OpenAI rows record the same capability as post_commit. The row files use two conventions; one must be chosen when they are merged.
- alibaba-cloud: Regions are not modelled. The client always dials the Beijing legacy host (config.rs:574) unless an endpoint override is set, while several rows are Beijing-only models and qwen3-asr-flash is the only model in US (Virginia), where a workspace id is mandatory. Keys are bound to a region.
- alibaba-cloud: gummy-realtime-v1 and gummy-chat-v1 stay 'ga' and enabled although the Chinese catalogue says they are planned to go offline (no date, not confirmed by the fact-check), and nobody established that the Paraformer-shaped run-task and parser fit their messages.
- alibaba-cloud: vendor_turn_signal 'silence' on the Fun-ASR and Qwen-Audio run-task rows is a guess. The client sends semantic_punctuation_enabled=true by default (messages.rs:436), which the vendor documents for Paraformer as switching to semantic segmentation; whether other families honour it is unknown.
- alibaba-cloud: Synchronous file limits rest on conflicting vendor pages (10 MB and 2 GB; the lower is recorded). The billing unit is unconfirmed for qwen-audio-3.0-asr-flash, fun-asr-flash-2026-06-15 and most streaming rows, and no Alibaba transport has a measured or published latency.
