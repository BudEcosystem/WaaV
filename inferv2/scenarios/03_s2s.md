# WaaV Infer — Scenario Catalog 03: Speech-to-Speech / Full-Duplex / Conversational

> Family: **S2S / full-duplex / conversational**. Grounded in Moshi full-duplex (RQ-Transformer temporal+depth, Mimi 12.5 Hz, 17-stream interleave, per-codebook acoustic-delay), Hibiki speech-translation (source/target/inner-monologue streams), BayLing-Duplex variable-block turn-taking, and the **CASCADE** path (STT→LLM→TTS) WaaV also serves. Engine invariants from `INFER_ENGINE.md` §4/§9 and the failure catalog (Moshi F1–F10, SGLang G1–G11, vLLM-core H1–H9, literature L1–L16).
>
> **Pipeline tags:** `S2S` (native speech-in→speech-out LM) · `duplex` (simultaneous listen+speak, user stream always modeled) · `cascade` (STT→LLM→TTS, possibly heterogeneous DAG) · `translate-s2s` (Hibiki-style source→target with inner monologue). `(+sub)` names the dominant sub-axis.
> **Levels:** SIMPLE → INTERMEDIATE → COMPOUND → EXTREME.

---

## SIMPLE

### S2S-1 — Single full-duplex call, one slot, edge GB10
- Level: SIMPLE
- Pipeline: duplex (+lockstep)
- Axes: moshi, mimi-12.5hz, inline-mode, n=1, first-audio
- Scenario: One user on a Moshi-class model on an otherwise-idle GB10; engine runs Inline/Pipelined-single (B=1), ingesting Mimi user tokens and emitting Moshi tokens every 80 ms tick.
- System must: run the frame-synchronous lockstep loop degenerately at N=1 (CUDA-graph the fixed-shape temporal+depth step, persistent ring KV, wall-clock pace at 12.5 Hz); first-audio = frame_period + acoustic_delay·frame_period + step_time (~200 ms measured).
- If mishandled: edge pays DC machinery (queues/ledger) for one stream, or busy-spins the tick instead of 2 ms idle-sleep.

### S2S-2 — Cascade STT→LLM→TTS, sequential single turn
- Level: SIMPLE
- Pipeline: cascade
- Axes: stt-llm-tts, three-node-dag, ttfa, non-duplex
- Scenario: Push-to-talk: user finishes speaking, STT transcribes, LLM answers, TTS speaks. No overlap, no barge-in.
- System must: chain three typed stages (STT encoder micro-batch → LLM decode → TTS AR+codec) with delta-streaming TTS egress so first audio starts before the full LLM reply completes; gate readiness on warmup, not process-up.
- If mishandled: waits for whole LLM reply then whole TTS synth before any audio → multi-second dead air the user reads as a hang.

### S2S-3 — Backchannel-only ("mm-hm") while user speaks
- Level: SIMPLE
- Pipeline: duplex (+overlap)
- Axes: moshi, user-stream-modeled, low-energy-emit, no-turn-take
- Scenario: User is mid-sentence; the model emits a short affirmative backchannel without taking the turn.
- System must: keep emitting from output slots every tick while ingesting user slots (the user stream is *always* modeled, §9 item 6); a backchannel is just non-silence output frames, no turn-state transition.
- If mishandled: treats any model output as a turn-grab and cuts the user off, or suppresses output entirely (loses the natural overlap Moshi is built for).

### S2S-4 — Clean end-of-turn handoff
- Level: SIMPLE
- Pipeline: duplex (+turn-taking)
- Axes: smart-turn, eot-head, marker, lockstep
- Scenario: User stops talking; the model should begin its reply at the right moment, not too eagerly and not after an awkward gap.
- System must: read the per-step end-of-turn/semantic-VAD head (§9 item 7) to detect EoT; the marker for the turn boundary fires at `now + delay_tokens + buffered_frames` via a step-ordered heap so the boundary lands after the delayed pipeline drains.
- If mishandled: declares EoT at input-exhaustion and clips the user's last delayed words, or barges in on a mid-sentence pause.

### S2S-5 — Slot release on clean hangup
- Level: SIMPLE
- Pipeline: duplex (+lifecycle)
- Axes: slot-recycle, reset-slot, used-total-slots
- Scenario: A duplex caller hangs up cleanly after the model finishes its last sentence.
- System must: free the slot only after `offset ≥ real_end` (tail drained), via one transactional `reset_slot(i)` fanning to KV pointers + conv rings + sampler RNG + word buffers + offset + host state; bump the `used/total_slots` gauge.
- If mishandled: frees on disconnect while the tail is still emitting (truncated goodbye) or never frees (slot leak shrinks capacity).

### S2S-6 — Two clocks, one stream (Mimi 12.5 Hz in, 24 kHz out)
- Level: SIMPLE
- Pipeline: duplex (+sample-rate)
- Axes: two-clocks, sr-vs-fr, resample, post-batch-codec
- Scenario: A duplex model thinks at 12.5 Hz frame-rate but produces 24 kHz audio that must reach an 8 kHz PSTN leg.
- System must: keep the AR step on the 12.5 Hz frame clock; run codec-decode + egress resample (24 k→8 k, anti-aliased, sinc) as a *post-batch* stage off the AR clock, repacketized to fixed 20 ms RTP via a jitter buffer.
- If mishandled: couples resampling into the AR tick (jitter/missed deadlines) or downsamples to 8 k without anti-aliasing (aliasing artifacts).

### S2S-7 — Cancelled turn ≠ completed turn
- Level: SIMPLE
- Pipeline: duplex (+barge-in)
- Axes: final-frame, cancelled-neq-completed, explicit-eos
- Scenario: The model is mid-reply; the user barges in, so the reply is cancelled rather than finished.
- System must: emit a terminal frame that *distinguishes* cancellation from completion (explicit FINAL/`is_done` sentinel vs a cancel sentinel, G2); "closed without a terminal frame" is a failure, never inferred from silence.
- If mishandled: consumer can't tell cancelled from stalled-producer → premature close, hung session, or a replayed stale tail.

### S2S-8 — Idle duplex slot stays in the batch (masked, not removed)
- Level: SIMPLE
- Pipeline: duplex (+lockstep-correctness)
- Axes: masked-neq-absent, exec-mask, static-shape
- Scenario: One of several duplex slots goes momentarily silent (user listening); its row must not be dropped from the rectangular batch.
- System must: keep the slot resident with `exec_mask=false`; substitute a valid input token (`is_init |= ~exec_mask` → force BOS) before the forward so the KV-gather never reads a sentinel; B stays constant so the one CUDA graph lasts forever.
- If mishandled: dropping the row changes B → re-capture every frame (catastrophic), or feeding sentinel `-2` → CUDA illegal-memory that kills all 64 users (F1).

### S2S-9 — Native S2S vs cascade for the same request
- Level: SIMPLE
- Pipeline: S2S | cascade
- Axes: path-choice, latency-budget, manifest-routing
- Scenario: An operator can serve a turn either by a native Moshi-class S2S model or by the STT→LLM→TTS cascade DAG.
- System must: route by manifest/config to the declared path; native S2S = one lockstep DAG (lower first-audio, true overlap), cascade = a 3-node heterogeneous DAG (swappable parts, higher first-audio); the *same* engine expresses both as data (P-7).
- If mishandled: hard-codes one path, losing either the duplex naturalness or the swappable-component flexibility.

### S2S-10 — Disable WS write-coalescing on the duplex egress
- Level: SIMPLE
- Pipeline: duplex (+transport)
- Axes: ws-flush, jitter, per-frame-write
- Scenario: Duplex audio frames (80 ms) are written to a WebSocket whose default buffering coalesces small writes.
- System must: set `write_buffer_size(0)` / flush per frame on every streaming route (F10) so an 80 ms-budget stream isn't given tens of ms of coalescing jitter.
- If mishandled: default coalescing adds 10s-of-ms jitter to the frame budget → audible cadence wobble.

### S2S-11 — Greeting prefill must not break the tick
- Level: SIMPLE
- Pipeline: duplex (+prefill-firewall)
- Axes: prefill-spike, admit-rate, cadence
- Scenario: A new duplex stream arrives carrying a short style/system conditioning prefix to prime the model.
- System must: admit ≤1 new stream's prefill per K frames and chunk any prefill exceeding one frame-budget's tokens (KV-length-aware predicted-latency budget, not raw token count, L10); steady-state ticks never skip.
- If mishandled: a prefill spike inflates per-tick time → 17–22 dropped frames (total dropout) for every active caller (§4.5).

### S2S-12 — Single-stream determinism for replay/debug
- Level: SIMPLE
- Pipeline: duplex (+numerics)
- Axes: per-stream-determinism, fp32-sampler, seeded-rng
- Scenario: A developer replays one captured user stream and expects the same model output twice.
- System must: accept *per-stream* determinism only (bitwise cross-batch is impossible under atomic reductions); fp32 sampler math, seeded per-slot RNG advanced through the masked-select, float64 Gumbel.
- If mishandled: promises global determinism it can't keep, or lets batch-position change the per-stream result (RNG offset not gated by exec_mask).

### S2S-13 — Warmup before the first duplex caller
- Level: SIMPLE
- Pipeline: duplex (+lifecycle)
- Axes: warmup-2-3-steps, full-mask, readyz-gate, capture-off-hot-path
- Scenario: A freshly started process must serve its first duplex caller without the first request paying graph-capture/lazy-init cost.
- System must: run 2–3 warmup steps with a full exec-mask + a `synchronize()` at startup to fill conv/KV boundary state and force CUDA-graph capture off the hot path; gate `/readyz` on warmup (and calibration) complete, not process-up (F6/C7).
- If mishandled: the first caller pays seconds of capture/init (first-request cliff), or /readyz returns ready while warmup is still running.

### S2S-14 — Init-token trap on a freshly admitted slot
- Level: SIMPLE
- Pipeline: duplex (+lockstep-correctness)
- Axes: is-init, bos-substitute, warming-slot, first-frames
- Scenario: A slot is admitted and is still in its first few frames where no real prior token exists yet.
- System must: treat the warming slot like a masked one — `is_init |= still_warming` forces the `initial`/BOS token via `where` before embedding (F1) so the KV-gather never reads stale/sentinel for a just-admitted slot.
- If mishandled: the new slot's first forward reads uninitialized state → NaN/illegal-memory that kills the whole batch (the init-token trap).

### S2S-15 — Opus vs PCM transport for one duplex leg
- Level: SIMPLE
- Pipeline: duplex (+transport)
- Axes: opus-pcm, 80ms-blocks, codec-negotiate, control-vs-data
- Scenario: A duplex caller connects over WebSocket and may send/receive either Opus or raw PCM in 80 ms / 1920-sample / 24 kHz blocks.
- System must: negotiate the transport codec at handshake, decode Opus→PCM on ingress and encode on egress as a post-batch stage, and keep the small control-plane (msgpack) separate from the data-plane (raw PCM, ref-held until send completes).
- If mishandled: couples transport-codec work into the AR tick, or mixes control and data planes so a control message blocks audio.

### S2S-16 — Eager fallback when graph capture OOMs at boot
- Level: SIMPLE
- Pipeline: S2S | duplex (+cuda-graph)
- Axes: enforce-eager, capture-oom, first-class-escape, pre-capture-check
- Scenario: On a memory-tight box, capturing the lockstep graph for the duplex cohort would OOM (graph+compile capture costs real memory).
- System must: make `enforce_eager` a first-class config + automatic fallback on capture failure (C8); run a pre-capture feasibility check at boot (reserve the graph-pool delta before admitting) so it fails at boot, not at request-1.
- If mishandled: capture OOMs after /health passed → crash-loop, or there's no eager escape so the box can't serve at all under memory pressure.

## INTERMEDIATE

### S2S-17 — 16 concurrent duplex calls, one lockstep cohort
- Level: INTERMEDIATE
- Pipeline: duplex (+lockstep-batch)
- Axes: cohort-by-frame-rate, 55x-at-64, fixed-slots, gb10
- Scenario: 16 callers on the same Moshi-class model on a GB10; all share the 12.5 Hz tick.
- System must: batch them as one `(model, frame_rate)` cohort over a fixed slot table (gather→step→scatter), riding the flat-to-64 decode curve; admit into free slots with backpressure; one shared CUDA graph at the fixed B.
- If mishandled: per-call serialization (16× the GPU time) or mixing frame-rate clocks into one tick (no common realtime period, §4.2).

### S2S-18 — Barge-in cancels the in-flight reply within one tick
- Level: INTERMEDIATE
- Pipeline: duplex (+barge-in)
- Axes: control-message, queue-jump, slot-free, reliable-abort
- Scenario: Mid-reply, the user starts speaking; the model must stop its own audio almost immediately and listen.
- System must: treat barge-in as a reliable control message (per-stage ack, not fire-and-forget PUB/SUB, G9) that jumps every stage's queue and frees/repurposes the stream's output within ≤1 tick; the user stream was already being modeled, so listening continues seamlessly.
- If mishandled: best-effort abort is dropped before a late stage connects → the model keeps talking over the user (the worst duplex failure).

### S2S-19 — Cascade barge-in must cancel the LLM, not just the TTS
- Level: INTERMEDIATE
- Pipeline: cascade (+barge-in)
- Axes: barge-in-cancels-llm, cross-stage-abort, partial-fire
- Scenario: In STT→LLM→TTS, the user interrupts while the LLM is still generating tokens that the TTS hasn't spoken yet.
- System must: propagate cancel upstream to the *LLM* stage (the duplex barge-in-cancels-LLM invariant), not only stop the TTS — else the LLM keeps burning tokens/compute for a reply no one will hear, and a queued tail could resume.
- If mishandled: TTS goes quiet but the LLM finishes and a stale reply gets spoken after the user's new turn (poisoned conversation history).

### S2S-20 — Acoustic-delay per-codebook ring correctness
- Level: INTERMEDIATE
- Pipeline: S2S | duplex (+acoustic-delay)
- Axes: rq-transformer, depth-decoder, per-codebook-delay, off-by-one
- Scenario: A Moshi/RQ-Transformer emits K codebooks per frame with per-codebook integer acoustic delays; the audio must reconstruct in time-order.
- System must: size each codebook's ring to `max_delay + 2` (the +2 guards the max-delay-write vs oldest-read collision), write at `(offset+delay[k])%CT`, read at `(offset−max_delay+gen_delay[k])%CT`; teacher-force codebooks≥1 to PAD while `step < acoustic_delay`.
- If mishandled: off-by-one collision corrupts a codebook → buzzing/metallic audio; reading before a real acoustic token exists → garbage first frames (F8).

### S2S-21 — Slot recycling across two different callers (privacy)
- Level: INTERMEDIATE
- Pipeline: duplex (+slot-recycle)
- Axes: reset-batch-idx, channel-id-guard, cross-user-leak
- Scenario: Caller A in slot 7 disconnects; caller B is admitted into slot 7 moments later.
- System must: run the transactional `reset_slot(7)` (KV pointers + conv rings + sampler + word buffers + offset reset, relying on positions/indices=0 + mask to make stale bytes unreachable) and guard outputs with a monotonic `channel_id` so any late frame/marker for A is dropped.
- If mishandled: B's attention reads A's KV and word buffer → A's words appear in B's transcript/audio (privacy disaster, F3).

### S2S-22 — Idle-then-resume a duplex slot (gated mutations)
- Level: INTERMEDIATE
- Pipeline: duplex (+lockstep-correctness)
- Axes: where-exec-mask, offset-gate, rope-phase, ring-poison
- Scenario: A caller falls silent for several seconds (long listen), then speaks again; the slot was masked throughout.
- System must: gate *every* per-stream mutation through `where(exec_mask, new, old)` — offset, KV scatter, conv-ring `previous`, `first`-frame flag, sampler RNG — so a masked slot's RoPE phase and ring cells don't advance while idle.
- If mishandled: one ungated mutation advances the offset/phase while idle → RoPE phase jump or poisoned ring cells on resume (silent corruption invisible in single-stream tests, F2).

### S2S-23 — Hibiki-style streaming speech translation (one direction)
- Level: INTERMEDIATE
- Pipeline: translate-s2s
- Axes: source-target-streams, inner-monologue, contextual-alignment-delay
- Scenario: Live EN speech in → ES speech out, simultaneously (Hibiki), with a text inner-monologue stream guiding the target.
- System must: interleave source-audio + inner-monologue-text + target-audio streams with per-stream integer delays (the multistream/delay engine, §9 item 5); the contextual-alignment delay lets the target lag source enough to be coherent but stay near-realtime.
- If mishandled: zero target delay → translates before enough source context (wrong/garbled output); excessive delay → no longer simultaneous (defeats the point).

### S2S-24 — End-of-turn detection under a hesitant speaker
- Level: INTERMEDIATE
- Pipeline: duplex (+turn-taking)
- Axes: eager-eot, smart-turn, pad-epad-silence
- Scenario: The user pauses mid-thought ("I'd like… umm…") and the model must not treat the pause as end-of-turn.
- System must: use the semantic EoT head (Smart-Turn-style) plus state tokens (PAD/EPAD/SILENCE, BayLing-Duplex) to distinguish a hesitation pause from a true turn-end; eager-EoT only fires on confident boundaries.
- If mishandled: silence-threshold EoT barges in on every filler pause → constant interruptions (the classic VAD-only failure).

### S2S-25 — Reasoning-LLM cascade: mask the slow first audio
- Level: INTERMEDIATE
- Pipeline: cascade (+reasoning-llm)
- Axes: latency-filler, two-tier, ttfa-30-100x, parallel-fire
- Scenario: The chosen LLM is a reasoning model 30–100× slower to first audio (9–18 s vs 0.17 s); the user must not hear dead air.
- System must: fire a non-committal latency-filler (a fast tier / cached acknowledgment) in parallel the instant EoT is detected, then crossfade to the reasoning reply when its first sentence is ready; barge-in cancels both tiers.
- If mishandled: 9–18 s of silence before any audio (user assumes the line dropped), or the filler and the real reply both play (double-talk).

### S2S-26 — Sentence-aggregated TTS feed from a streaming LLM
- Level: INTERMEDIATE
- Pipeline: cascade (+streaming-egress)
- Axes: sentence-lookahead, delta-only, partial-fire
- Scenario: The LLM streams tokens; the TTS should start speaking the first sentence while later sentences are still being generated.
- System must: aggregate LLM tokens to sentence/clause boundaries and partial-fire each completed unit into the TTS stage as delta-only audio (offline-concat == stream-concat byte-identical, I1/C1).
- If mishandled: cumulative re-decode from step 0 (O(N²), replays/truncation), or waits for the whole reply before speaking (kills the latency win).

### S2S-27 — Voice agent: tool-call mid-conversation
- Level: INTERMEDIATE
- Pipeline: cascade (+tool-call)
- Axes: partial-fire, tool-latency-mask, conversation-resume
- Scenario: A duplex voice agent needs a tool/API call (e.g. "checking your balance…") that takes a second or two.
- System must: speak a partial-fire bridge ("one moment…") while the tool runs off the audio path, keep ingesting the user stream (barge-in still cancels), then resume the reply with the tool result merged into context.
- If mishandled: the conversation freezes during the tool call (no audio, user repeats themselves), or the tool result is spoken into a turn the user already abandoned.

### S2S-28 — Multi-turn context accumulation within budget
- Level: INTERMEDIATE
- Pipeline: duplex (+context)
- Axes: ring-kv, bounded-context, ctx-1024-benign
- Scenario: A 3-minute duplex conversation accumulates context across many short turns, staying within the model's ~3000-token window.
- System must: keep the per-slot fixed ring KV (no paging) since context is bounded and benign even at ctx 1024 (§1.2); size the slot by the compute crossover, not the KV wall.
- If mishandled: reaches for paged KV machinery the bounded case doesn't need (allocation jitter → frame-deadline misses), or under-sizes the ring and wraps too early.

### S2S-29 — STT side of a cascade is a frame-sync encoder
- Level: INTERMEDIATE
- Pipeline: cascade (+stt)
- Axes: ctc-rnnt-tdt, cache-aware-encoder, lockstep-chunk
- Scenario: The cascade's STT is a streaming CTC/RNN-T encoder (parakeet/FastConformer-T) feeding partial transcripts to the LLM.
- System must: run the encoder as a lockstep chunk-batched stage emitting cache-aware deltas (bounded encoder state, not full re-encode — the 560-streams/H100 contract, L11) so partials reach the LLM with low latency.
- If mishandled: full-utterance re-encode per chunk (no partials, high latency) or unbounded encoder state (memory growth over a long call).

### S2S-30 — Sampler outside the CUDA graph (TTS needs multinomial)
- Level: INTERMEDIATE
- Pipeline: S2S | duplex (+cuda-graph)
- Axes: multinomial-vs-argmax, graph-safe, gumbel-argmax
- Scenario: The lockstep step is CUDA-graphed for the edge latency win, but the acoustic head samples (multinomial), which is not graph-safe.
- System must: sample *outside* the captured region or use a graph-safe gumbel-argmax inside (C2/F7); wrap graphed callables with a shape+scalar-identity assert so a mismatch is a loud crash, not stale-graph corruption.
- If mishandled: graph capture silently breaks sampling (deterministic argmax everywhere → robotic/identical output) or forces eager, losing the 1.21×@B1 edge win.

### S2S-31 — All-duplex-slots-idle frame
- Level: INTERMEDIATE
- Pipeline: duplex (+scheduler-loop)
- Axes: exec-mask-any, idle-sleep, no-busy-spin
- Scenario: For one tick, every resident duplex caller is silent and the model is mid-listen (no output due) on all of them.
- System must: apply admissions/resets/control-plane first, compute exec_mask, and run the kernel *only if* `exec_mask.any()`, else short-sleep 1–2 ms (never run the dense kernel on an all-False batch, F6/G3).
- If mishandled: runs a full forward on an all-masked batch (wasted bandwidth) or busy-spins the loop (starves co-located stages, the GIL-starvation analog).

### S2S-32 — NaN logit on the acoustic head → reject the frame
- Level: INTERMEDIATE
- Pipeline: S2S | duplex (+numerics)
- Axes: nan-reject, repeat-prev, codec-silence, always-on-check
- Scenario: A rare numerical blowup produces a NaN/Inf in the acoustic logits for one slot's frame.
- System must: run an always-on `logits.isnan().any()` reduction and reject the frame (repeat previous frame / emit codec-silence / greedy-resample), since the argmax-style sampler would otherwise pick a garbage codec token (H1).
- If mishandled: argmax of a NaN row → an audible pop with zero error signal (the silent-glitch the default-off check misses).

### S2S-33 — Per-stage batch sizes differ (AR≥4, codec=1)
- Level: INTERMEDIATE
- Pipeline: S2S | cascade (+stage-dag)
- Axes: decoupled-batch, codec-round-robin, audio-gaps
- Scenario: A native-S2S DAG has an AR backbone feeding a shared codec/vocoder stage under concurrency.
- System must: give the AR stage `max_num_seqs ≥ 4` to pipeline and the codec stage `1` (its window round-robins); never inherit one uniform batch size across stages (C6/RFC #2568).
- If mishandled: a uniform default of 1 starves AR pipelining; a uniform default >1 makes the codec window round-robin → audio gaps under concurrency.

### S2S-34 — Marker/flush on a non-streaming (POST) duplex request
- Level: INTERMEDIATE
- Pipeline: duplex (+marker-flush)
- Axes: trailing-silence, terminate-on-marker, delay-pipeline
- Scenario: A one-shot POST submits a finite user clip to the streaming-core duplex model and expects the complete reply.
- System must: append the real audio + a marker + ~10 s trailing silence to flush the delay pipeline, and terminate on the marker (not input-exhaustion), so the delayed final words/audio are emitted (F5).
- If mishandled: terminates at input-exhaustion → the last delayed frames are truncated (clipped reply).

### S2S-35 — Co-resident STT and duplex S2S on one GB10
- Level: INTERMEDIATE
- Pipeline: duplex | cascade (+co-resident)
- Axes: shared-bandwidth, duty-ledger, placement
- Scenario: A duplex S2S model and a separate batched STT model are loaded on the same GB10 sharing the ~273 GB/s LPDDR ceiling.
- System must: budget the *shared bandwidth* as a schedulable resource (per-substrate duty ledger + shared-bandwidth ledger); prefer to overlap the memory-bound AR decode with the compute-bound STT encoder, and place the codec on the NPU/CPU to free GPU bandwidth.
- If mishandled: both stages saturate the one bandwidth ceiling concurrently → both miss frame deadlines (admission must budget the shared pool, §3.4).

### S2S-36 — Hybrid KV: ref-audio/system-prompt prefix is shared
- Level: INTERMEDIATE
- Pipeline: S2S | duplex (+prefix-cache)
- Axes: radix-prefix, extra-key, 86-percent-hit, ring-suffix
- Scenario: Many duplex sessions use the same cloned voice and the same system prompt (the top commercial multi-tenant workload).
- System must: serve a hybrid KV — a radix/prefix-cache (paged) for the deterministic ref-audio + system-prompt prefix (Fish-S2 ~86% hit, L1), keyed by a content hash over *all* codebooks (`extra_key`, G1), plus the per-slot ring for the per-utterance suffix.
- If mishandled: a pure per-slot ring recomputes the shared prefix every request (forfeits ~86% cacheable work), or a token-id-only cache key cross-contaminates different ref-audios → wrong-voice output (G1).

### S2S-37 — Zero-shot (no ref-audio) duplex must keep legit prefix-sharing
- Level: INTERMEDIATE
- Pipeline: duplex (+prefix-cache)
- Axes: extra-key-none, zero-shot, genuine-prefix-share
- Scenario: Some duplex sessions use no voice-clone reference (zero-shot voice), so their conditioning prefix really is identical and *should* share KV.
- System must: set `extra_key=None` for genuinely-identical (zero-shot) prefixes so legit prefix-sharing survives, while ref-audio sessions get a content-hash key that prevents cross-contamination (G1).
- If mishandled: hashing zero-shot prefixes needlessly forfeits sharing, or omitting the key on ref-audio sessions cross-contaminates voices.

### S2S-38 — Semantic-VAD false-trigger on background noise
- Level: INTERMEDIATE
- Pipeline: duplex (+turn-taking)
- Axes: eot-head, noise-robust, false-barge-in, energy-vs-semantic
- Scenario: A duplex caller in a noisy café; transient background noise (door slam, nearby talk) could be misread as the user starting to speak.
- System must: drive turn-taking from the *semantic* EoT/VAD head (not raw energy) so non-speech noise doesn't trigger a spurious barge-in or turn-grab; the user stream stays modeled but only confident speech onsets transition turn-state.
- If mishandled: every background transient triggers a false barge-in (the agent keeps stopping itself) or a false turn-grab (talks over real silence).

### S2S-39 — Delay-sign selects STT vs TTS vs S2S on the same engine
- Level: INTERMEDIATE
- Pipeline: S2S | translate-s2s (+interleave)
- Axes: text-audio-delay-sign, one-knob, multistream-interleave
- Scenario: The same multistream/delay engine must serve an STT task (audio leads text) and a TTS task (text leads audio) and an S2S/translation task by configuration.
- System must: switch behavior via the single text↔audio delay-sign knob over the K=2Q+1 interleaved streams (§9 item 5), writing/reading at `(offset+delay)%context` per stream; no separate code path per task.
- If mishandled: forks the engine per task (maintenance burden, drift) or sets the wrong delay sign (STT logic on a TTS stream → garbage alignment).

### S2S-40 — Depformer/code-predictor as the MTP acoustic accelerator
- Level: INTERMEDIATE
- Pipeline: S2S | duplex (+mtp)

- Scenario: Live translation where the source arrives at 16 kHz (STT-grade) but the target voice is a 24 kHz codec destined for a 48 kHz HD leg.
- System must: keep the AR/inner-monologue on the frame clock and run two independent post-batch resample chains (ingress any→16 k; egress 24 k→48 k) off the AR clock, each persistent per-stream; the two clocks (SR vs FR) stay decoupled.

### S2S-79 — Barge-in arrives during the acoustic-delay warm-up window

### S2S-86 — Prefill firewall under a reconnect storm into a saturated duplex cohort
