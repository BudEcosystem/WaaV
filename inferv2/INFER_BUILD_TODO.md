# WaaV Infer v2.1 — production build (tracked implementation TODO)

This is the build-tracking document an engineer executes top-to-bottom to extend the live 6-crate `waav-infer` (`/home/bud/ditto/waav/waav-infer/` — `waav-infer-core` 16-arm registry + coarse `TtsModel`/`SttModel` + `StaticGraph`, `waav-infer-backend-api`, `waav-infer-backend-ort`, `waav-infer-server`, `waav-infer-components`, plus the `torch_runtime` sidecar) to the `INFER_ENGINE_V2.md` architecture (`WaaV/inferv2/INFER_ENGINE_IMPL.md`) via **extreme TDD on GB10** (sm_121, ORT-CUDA EP under `gb10-env.sh`). Two invariants override everything: **(1) accuracy is sacred** — the default path is bit-faithful at native precision (no quant/spec-decode/approximate-attention by default; any deviation is opt-in, per-model, behind a `verify-vs-native` accuracy/MOS stamp), enforced by the standing **AR-compounding identity test** (emitted codes IDENTICAL, not close); **(2) correctness under multi-tenancy is sacred** — every per-slot mechanism (`masked ≠ absent`, ring-KV isolation, slot-leak) is tested at `max_num_seqs ≥ 4` with the bit-identical-to-serial gate. Every task is **RED (write the failing test) → GREEN (minimal impl) → REFACTOR**, then **live-validated on GB10** where a GPU is in the loop; new code lands in additive crates/trait-methods so the 16 registry arms + `StaticGraph` + Path-A one-shot models stay untouched and `git revert` of any milestone leaves a working engine.
